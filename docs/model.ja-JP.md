# モデル

モデルは `libriichi` が生成する Mortal v4 の観測を基にします。入力形状は `1028 × 34` です。

## 構成

モデルは Mortal の観測に、4 人全員の順位を表す 16 個の one-hot チャンネルを加えます。先頭の 886 チャンネルは局面と操作対象プレイヤーに見えている手牌を表し、各予測ヘッドで共有します。残りの 142 チャンネルは行動段階、合法手、単人 EV テーブルを表し、方策経路だけで使用します。

既定の構成は次のとおりです。重みファイルには学習時の構成が記録されます。

| 部分 | 既定の構成 | パラメータ数 |
| --- | --- | ---: |
| 局面エンコーダー | 192 チャンネル、36 個の pre-activation residual block、channel attention、768 次元出力 | 9,529,040 |
| 状態予測 | 768 次元アダプター | 1,228,862 |
| 将来予測 | 640 次元アダプター | 666,512 |
| 方策コンテキスト | 96 チャンネル、4 個の pre-activation residual block、256 次元出力 | 556,856 |
| 行動方策 | 640 次元アダプター、46 個の内部アクション | 685,486 |
| 合計 |  | 12,666,756 |

状態予測には、対戦相手のシャンテン数、振聴または役なし、牌ごとの放銃率、手牌枚数、牌山枚数が含まれます。将来予測には、ドラ数、打点、局結果、局収支、最終順位、最終持ち点が含まれます。方策は牌譜中の選択から推薦強度を学習します。

各教師あり目的は、学習中に推定される不確実性の重みで調整されます。重みはモデル構成とともにチェックポイントへ保存され、検証ログには有効な重みが記録されます。

## 教師ラベル

- シャンテン数、振聴または役なし、牌ごとの放銃率は、各イベント時点の完全な手牌情報から算出します。
- 手牌と未公開牌山は `0..4`、3 種類の赤5は別に `0..1` の分類問題として学習します。
- ドラ数と打点は、そのプレイヤーが最終的に和了した局面だけを損失計算に使用し、離散分布と独立したスカラー値を同時に学習します。ドラ数は `0..6` と `7+`、打点は子の4翻30符ロン7700点、三倍満、ダブル役満、複合役満を含む59種類の精算値に分類します。
- 局結果は、流局、4通りのツモ、ダブロンとトリプルロンを含む28通りのロンを学習します。4人の和了率と放銃率は、この33通りの結果から算出します。
- 最終順位は 4 人の順位に対応する 24 通りの同時分布として学習します。
- 行動ラベルには Mortal v4 の 46 個の内部アクションと合法手マスクを使用します。エンジンは内部の条件付きアクションを、完全なプロトコル候補に合成して返します。

## データ分割

2025 年の牌譜からファイル名ハッシュで安定して `1/20` を選び、8,944 対局を学習に使用します。検証には、Mortal のデータ準備処理と同じ MD5 分割で留保した 2026 年の 246 対局を使用します。

各公開イベントにつき、固定規則で選んだ 1 視点以上を保存します。行動ラベルを付けられる場合は、実際に行動したプレイヤーまたは明示的に見送ったプレイヤーの視点も加えます。観測は 2 枚のビットマップと疎な `float16` 値で圧縮して保存します。同じドラ表示牌が複数ある場合は重複して数え、打点からは本場と供託を除きます。

## テスト学習の実行

Python 3.11 の学習環境を用意し、`scripts/run-training-test.ps1` を実行します。2025 年の牌譜フォルダー、2026 年のアーカイブ、Mortal の Python モジュールを指定すると、2 つのデータセットを再変換し、1 epoch の学習と推論用重みの出力を実行します。
