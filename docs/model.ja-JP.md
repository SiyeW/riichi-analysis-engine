# モデル

モデルは公開局面と意思決定コンテキストを別々に扱います。保存時とモデル呼び出し時には、両者をバージョン付きの `1157 × 34` 入力としてまとめます。

## 構成

公開局面入力は 1001 チャンネルで、操作対象プレイヤーから見える手牌、ルール、4 人分の対称な公開履歴、現在のイベントを表します。解析用の各分岐は、この入力だけを使用します。

意思決定コンテキストは、`libriichi` の Mortal v4 観測から選んだ 156 チャンネルです。自家のドラ概要、シャンテン数と振聴状態、行動段階、合法手、単人効率テーブルを表し、行動方策だけが使用します。

既定の構成は次のとおりです。重みファイルには学習時の構成が記録されます。

| 部分 | 既定の構成 | パラメータ数 |
| --- | --- | ---: |
| 共有局面エンコーダー | 256 チャンネル、30 個の pre-activation residual block | 12,849,888 |
| 対戦相手解析 | 24 個の residual block、1024 次元出力 | 12,507,166 |
| 手牌と牌山 | 8 個の residual block、768 次元出力 | 4,516,400 |
| ドラと打点 | 6 個の residual block、768 次元出力 | 4,563,532 |
| 局解析 | 6 個の residual block、768 次元出力 | 4,084,646 |
| 対局解析 | 4 個の residual block、768 次元出力 | 3,274,108 |
| 意思決定コンテキスト | 144 チャンネル、6 個の residual block、384 次元出力 | 1,266,134 |
| 行動方策 | 24 個の residual block、1024 次元出力、46 個の内部アクション | 12,295,118 |
| 合計 |  | 55,356,992 |

対戦相手解析は、シャンテン数、振聴または役なし、牌ごとの放銃率を予測します。ほかの分岐は、手牌と牌山、ドラと打点、局結果と収支、最終順位と持ち点をそれぞれ予測します。行動方策は同じ公開局面と専用の意思決定コンテキストを組み合わせ、牌譜中の選択から推薦強度を学習します。

各教師あり目的は、学習中に推定される不確実性の重みで調整されます。重みはモデル構成とともにチェックポイントへ保存され、検証ログには有効な重みが記録されます。

## 教師ラベル

- シャンテン数、振聴または役なし、牌ごとの放銃率は、各イベント時点の完全な手牌情報から算出します。
- 手牌と未公開牌山は `0..4`、3 種類の赤5は別に `0..1` の分類問題として学習します。
- ドラ数と打点は、そのプレイヤーが最終的に和了した局面だけを損失計算に使用します。ドラ数は `0..6` と `7+` に分類し、期待値も個別に出力します。打点は実際に成立する59種類の精算値に分類し、親と子で成立しない値を除外します。子の4翻30符ロンは7700点で、三倍満、ダブル役満、複合役満にも対応します。
- 局結果は、流局、4通りのツモ、ダブロンとトリプルロンを含む28通りのロンを学習します。4人の和了率と放銃率は、この33通りの結果から算出します。
- 最終順位は 4 人の順位に対応する 24 通りの同時分布として学習します。
- 行動ラベルには Mortal v4 の 46 個の内部アクションと合法手マスクを使用します。エンジンは内部の条件付きアクションを、完全なプロトコル候補に合成して返します。

## データ分割

学習データは非公開の外部 manifest から読み込みます。

各公開イベントでは、固定規則で選んだ 1 視点だけを解析出力の学習に使用します。行動ラベルを付けられる場合は、実際に行動したプレイヤーまたは明示的に見送ったプレイヤーの視点も行動方策の学習に使用します。観測は 2 枚のビットマップと疎な `float16` 値で圧縮して保存します。同じドラ表示牌が複数ある場合は重複して数え、打点からは本場と供託を除きます。

## テスト学習の実行

Python 3.11 の学習環境を用意し、ローカルで作成した manifest を変換処理へ渡してから、生成したパックを学習に使用します。
