# モデル

`libriichi` が生成する Mortal v4 の公開情報を使用します。入力形状は `1012 × 34` です。

## 構成

| 部分 | 構成 | パラメータ数 |
| --- | --- | ---: |
| 共有エンコーダー | 256 チャンネル、54 個の pre-activation residual block、channel attention、1024 次元出力 | 23,663,488 |
| 状態予測 | 1024 次元アダプター | 1,900,350 |
| 将来予測 | 768 次元アダプター | 990,216 |
| 行動方策 | 46 アクション | 47,150 |
| 合計 |  | 26,601,204 |

状態予測分岐は 1024 次元の中間層から 830 個、将来予測分岐は 768 次元から 264 個の値を出力します。どちらのアダプターも出力を低ランクに制限しません。

状態予測には、対戦相手のシャンテン数、振聴または役なし、牌ごとの放銃率、手牌枚数、牌山枚数が含まれます。将来予測には、ドラ数、打点、局結果、局収支、最終順位、最終持ち点が含まれます。行動方策は牌譜の実際の選択を学習します。

## 教師ラベル

- シャンテン数、振聴または役なし、牌ごとの放銃率は、各イベント時点の完全な手牌情報から算出します。
- 手牌と未公開牌山は `0..4`、3 種類の赤5は別に `0..1` の分類問題として学習します。
- ドラ数と打点は、そのプレイヤーが最終的に和了した局面だけを損失計算に使用し、離散分布と独立したスカラー値を同時に学習します。ドラ数は `0..6` と `7+`、打点は子の4翻30符ロン7700点、三倍満、ダブル役満、複合役満を含む59種類の精算値に分類します。
- 局結果は、誰かが和了するかどうかと、和了が発生した場合に各プレイヤーが和了者となるかどうかを個別に学習します。ダブロンやトリプルロンでは複数人が同時に成立します。
- 最終順位は 4 人の順位に対応する 24 通りの同時分布として学習します。
- 行動ラベルには Mortal v4 の 46 アクションと合法手マスクを使用します。

## データ分割

2025 年の牌譜からファイル名ハッシュで安定して `1/20` を選び、8,944 対局を学習に使用します。検証には、Mortal のデータ準備処理と同じ MD5 分割で留保した 2026 年の 246 対局を使用します。

各公開イベントにつき、固定規則で選んだ 1 視点以上を保存します。行動ラベルを付けられる場合は、実際に行動したプレイヤーまたは明示的に見送ったプレイヤーの視点も加えます。観測は 2 枚のビットマップと疎な `float16` 値で圧縮して保存します。同じドラ表示牌が複数ある場合は重複して数え、打点からは本場と供託を除きます。

## テスト学習の実行

Python 3.11 の学習環境を用意し、`scripts/run-training-test.ps1` を実行します。2025 年の牌譜フォルダー、2026 年のアーカイブ、Mortal の Python モジュールを指定すると、manifest の作成、変換、1 epoch の学習、推論用重みの出力を順番に実行します。変換済みの対局 shard は再利用されます。
