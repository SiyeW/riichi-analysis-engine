# 模型

模型以 `libriichi` 生成的 Mortal v4 观测为基础，模型输入形状为 `1028 × 34`。

## 结构

模型在 Mortal 观测中补充四家顺位的 16 个 one-hot 通道。前 886 个通道编码当前局面和受控玩家已知的手牌，由局面编码器共享给各项预测。其余 142 个通道包含动作阶段、合法动作和单人 EV 表，只进入策略路径。

默认配置如下。权重文件会记录实际使用的结构参数。

| 部分 | 默认结构 | 参数量 |
| --- | --- | ---: |
| 局面编码器 | 192 通道、36 个预激活残差块、通道注意力、768 维输出 | 9,529,040 |
| 状态预测 | 768 维适配层 | 1,228,862 |
| 后续结果 | 640 维适配层 | 666,512 |
| 策略上下文 | 96 通道、4 个预激活残差块、256 维输出 | 556,856 |
| 动作策略 | 640 维适配层、46 个内部动作 | 685,486 |
| 合计 |  | 12,666,756 |

状态预测包括对手向听、振听或无役、牌张放铳率、对手暗牌数量和牌山数量。后续结果包括对手宝牌与打点、小局结果、局收支、终局顺位和分数。策略使用牌谱中的实际选择学习推荐强度。

各监督项在训练中使用可学习的不确定性权重平衡。权重与模型配置一同写入检查点，验证日志会记录每项的有效权重。

## 标签

- 对手向听、振听或无役、牌张放铳率使用逐事件完整手牌状态计算。
- 对手暗牌和未公開牌山使用 `0..4` 分类标签；三种红五另使用 `0..1` 分类标签。
- 对手宝牌和打点只在该玩家最终和牌时计算损失，同时学习离散分布和独立标量。宝牌分为 `0..6` 和 `7+`；打点使用规则中实际存在的 59 个结算档位，包括子家四番 30 符荣和 7700 点、三倍满、双倍役满和叠加役满。
- 小局结果学习流局、四种自摸和包含双响、三响的 28 种荣和结果；四家的和牌率与放铳率由这 33 种结果得出。
- 终局顺位使用四家顺位的 24 种联合排列。
- 动作标签使用 Mortal v4 的 46 个内部动作和合法动作掩码。引擎会把内部条件动作合成为协议中的完整合法候选后返回。

## 数据划分

训练集从 2025 年牌谱中按文件名哈希稳定选取 `1/20`，共 8,944 局。验证集使用 2026 年牌谱中与 Mortal 数据准备脚本相同的 MD5 分桶留出，共 246 局。

每个公开事件至少保留一个固定视角；存在可监督动作时，同时保留作出动作或明确放弃动作的视角。观测用双位图和稀疏 `float16` 数值压缩保存。宝牌标签会重复计算相同的宝牌指示牌；打点标签不包含本场和供托。

## 运行测试训练

建立 Python 3.11 训练环境后，运行 `scripts/run-training-test.ps1`。指定 2025 年牌谱目录、2026 年压缩包和 Mortal Python 模块目录后，脚本会重新转换两个数据集、训练一轮并导出推理权重。
