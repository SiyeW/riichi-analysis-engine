# 模型

模型使用相互分离的公开局面输入和决策上下文。存储和模型调用时，两者合并为 `1157 × 34` 的版本化输入。

## 结构

公开局面输入包含 1001 个通道，编码受控玩家的可见手牌、规则状态、四家对称的公开历史和当前事件。所有分析分支只使用这组输入。

决策上下文包含从 `libriichi` Mortal v4 观测中选取的 156 个通道，编码自家宝牌概况、向听与振听状态、动作阶段、合法动作和单人效率表。这组输入只进入动作策略分支。

默认配置如下。权重文件会记录实际使用的结构参数。

| 部分 | 默认结构 | 参数量 |
| --- | --- | ---: |
| 共享局面编码 | 256 通道、30 个预激活残差块 | 12,850,400 |
| 对手分析 | 24 个残差块、1024 维输出 | 11,971,614 |
| 暗牌与牌山 | 8 个残差块、768 维输出 | 4,516,400 |
| 宝牌与打点 | 6 个残差块、768 维输出 | 4,563,532 |
| 小局分析 | 6 个残差块、768 维输出 | 4,084,646 |
| 终局分析 | 4 个残差块、768 维输出 | 3,274,108 |
| 决策上下文 | 144 通道、6 个残差块、384 维输出 | 1,266,134 |
| 动作策略 | 24 个残差块、1024 维输出、46 个内部动作 | 12,295,118 |
| 合计 |  | 54,821,952 |

对手分析包括向听、振听或无役和牌张放铳率。其余分支分别预测对手暗牌与牌山、对手宝牌与打点、小局结果与收支、终局顺位与分数。动作策略使用相同的公开局面和独立的决策上下文，从牌谱中的实际选择学习推荐强度。

各监督项在训练中使用可学习的不确定性权重平衡。权重与模型配置一同写入检查点，验证日志会记录每项的有效权重。

## 标签

- 对手向听、振听或无役、牌张放铳率使用逐事件完整手牌状态计算。
- 对手暗牌和未公開牌山使用 `0..4` 分类标签；三种红五另使用 `0..1` 分类标签。
- 对手宝牌和打点只在该玩家最终和牌时计算损失。宝牌分为 `0..6` 和 `7+`，并提供独立的期望值；打点使用规则中实际存在的 59 个结算档位，并按庄家或子家排除不可能的分数。子家四番 30 符荣和为 7700 点，支持三倍满、双倍役满和叠加役满。
- 小局结果学习流局、四种自摸和包含双响、三响的 28 种荣和结果；四家的和牌率与放铳率由这 33 种结果得出。
- 终局顺位使用四家顺位的 24 种联合排列。
- 动作标签使用 Mortal v4 的 46 个内部动作和合法动作掩码。引擎会把内部条件动作合成为协议中的完整合法候选后返回。

## 数据划分

训练数据通过非公开的外部 manifest 提供。

每个公开事件至少保留一个固定视角；存在可监督动作时，同时保留作出动作或明确放弃动作的视角。观测用双位图和稀疏 `float16` 数值压缩保存。宝牌标签会重复计算相同的宝牌指示牌；打点标签不包含本场和供托。

## 运行测试训练

建立 Python 3.11 训练环境后，使用本地准备的 manifest 运行转换，再对生成的数据包执行训练。
